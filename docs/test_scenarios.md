# Тестовые сценарии

Каждый сценарий описывает вход (запрос, локацию, параметры), то, что должен вернуть поиск,
и ожидаемый тип ответа всей системы (`POST /recommend`). Поисковая часть сценариев
автоматизирована в `tests/test_scenarios.py`:

```bash
python scripts/build_index.py      # один раз, ~2 мин на первом запуске (скачивание модели)
python -m pytest tests -q
```

**Опорные точки:**
- **Байтерек** — `51.1283, 71.4305`, Левый берег, центр туристической зоны.
- **Старый центр** — `51.1694, 71.4491`, Правый берег.
- **За городом** — `51.30, 71.00`, степь, POI рядом нет.

**Время** везде задаётся явно через `now_iso` (часовой пояс Астаны, UTC+5), чтобы результат
воспроизводился. 16.10.2026 — пятница.

**Данные:** 958 POI из OpenStreetMap, срез от 16.10.2026. Часы работы указаны у ~35% мест,
описания почти отсутствуют. От этого зависят ожидания ниже.

## S1. Поработать с ноутбуком

| Вход | |
|---|---|
| query | «тихое место с кофе и розеткой» |
| локация | Байтерек, `max_distance_m=1500` |
| время | пятница 13:00 |

**Поиск:** топ-3 — кафе; хотя бы одно из первых пяти с тегом `wifi`. Тега «розетки» в OSM
почти нет, поэтому «розетка» переводится в буст по `wifi` (место, где можно работать).

**Ожидаемый ответ:** 1-3 кафе с расстоянием и временем пешком. Статус `confirmed_open`
ставится только при известных часах. В `used_data.tags` есть `wifi`. Если наличие розеток
модель лишь предполагает, это помечается как `generated_idea` или оговаривается в «почему»,
но не подаётся как факт.

## S2. Просто погулять

| Вход | |
|---|---|
| query | «погулять на свежем воздухе» |
| локация | Байтерек, 2000 м |
| время | пятница 13:00 |

**Поиск:** топ-3 — места с тегом `outdoor` (парки, скверы, памятники).

**Ожидаемый ответ:** у парков почти никогда нет часов работы, поэтому статус `unknown`
с пояснением «часы не указаны». Система не пишет «открыто». Хороший кандидат
на мини-маршрут из 3 точек.

## S3. Культурная программа, большой радиус

| Вход | |
|---|---|
| query | «музей история» |
| локация | Байтерек, 5000 м |
| время | пятница 13:00 |

**Поиск:** первый результат — `museum` или `gallery`.

**Ожидаемый ответ:** честное время пешком (до 50+ мин). Если ближайший музей далеко,
система предлагает такси или транспорт как `generated_idea` либо подсказывает уменьшить
радиус.

## S4. Семейный ужин, национальная кухня

| Вход | |
|---|---|
| query | «поесть казахскую кухню с семьёй» |
| локация | Байтерек, 2000 м |
| время | пятница 13:00 |
| group_size | 4 |

**Поиск:** минимум 2 из топ-3 имеют `cuisine_kazakh` или `cuisine_regional`.

**Ожидаемый ответ:** рестораны с национальной кухней. В «что делать» — что заказать
на компанию (идея модели, `generated_idea`). Блюда не выдаются за меню конкретного
заведения, если их нет в данных.

## S5. Поздний вечер, многое закрыто

| Вход | |
|---|---|
| query | «поесть» |
| локация | Байтерек, 2000 м |
| время | пятница 23:40 |

**Поиск:** в топ-3 нет `likely_closed`. Места, закрывающиеся в полночь, получают
`likely_open` с причиной «закрывается примерно через 20 мин». Закрытые по расписанию
опускаются вниз.

**Ожидаемый ответ:** предупреждение о скором закрытии и приоритет круглосуточным местам.
Нельзя отправлять человека туда, где по данным уже закрыто.

## S6. Доступность для маломобильных

| Вход | |
|---|---|
| query | «доступно для колясок» |
| локация | Байтерек, 2000 м |
| accessible | `true` |

**Поиск:** все топ-3 имеют тег `wheelchair` (`wheelchair=yes` в OSM).

**Ожидаемый ответ:** в `used_data.filters` видно, что доступность учтена. Дисклеймер:
данные о доступности собраны волонтёрами OSM и могут быть неполными, лучше уточнить
у заведения.

## S7. Запрос на английском (турист)

| Вход | |
|---|---|
| query | «quiet place to read a book» |
| локация | Байтерек, 4000 м |
| lang | `en` |

**Поиск:** первый результат — `library`. Мультиязычная модель эмбеддингов сопоставляет
английский запрос с русскими названиями.

**Ожидаемый ответ:** объяснения на английском, названия мест — как в данных.

## S8. Пользователь за городом

| Вход | |
|---|---|
| query | «кофе» |
| локация | `51.30, 71.00` |
| радиус | 2000 м |

**Поиск:** пустой список.

**Ожидаемый ответ:** «рядом ничего не найдено» и предложение увеличить радиус.

## S9. Бессмысленный запрос

| Вход | |
|---|---|
| query | «ыфвафыва» |
| локация | Байтерек |

**Поиск:** что-то найдётся (ближайшие места), но у всех `relevance < 0.6`.

**Ожидаемый ответ:** система переспрашивает или явно говорит, что показывает просто
ближайшие места. Ориентир для генерации: `relevance < 0.5` — слабое совпадение.

---

## Инварианты (проверяются на любом запросе)

- `distance_m <= max_distance_m`, `walk_min >= 1`, `0 <= relevance <= 1`.
- Нет `opening_hours` → `open_status = "unknown"`.
- Нераспознанный формат часов → `unknown` с текстом исходной строки в `open_reason`.
- Каждый `poi_id` в ответе API присутствует в результатах retrieval (проверяет роль B).

## Как читать поля поиска

| Поле | Смысл |
|---|---|
| `relevance` | Семантическая близость (0-1) плюс буст за запрошенные удобства (wifi, коляски, халяль…). Выше 0.7 — хорошее совпадение, ниже 0.5 — слабое. |
| `open_status` | `confirmed_open`: открыто по расписанию OSM и до закрытия больше 30 мин. `likely_open`: закрывается в ближайшие 30 мин. `likely_closed`: вне расписания. `unknown`: часов нет или их не удалось разобрать. |
| `walk_min` | Прямое расстояние × 1.3 (поправка на улицы) при скорости 4.5 км/ч. |
