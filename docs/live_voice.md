# Голосовой разговор

Экспериментальный режим Gemini Live внутри Streamlit. Обычный микрофон в поле
ввода остаётся диктовкой через OpenRouter; новый переключатель включает разговор.

## Поток данных

1. Пользователь нажимает «Начать разговор» и разрешает микрофон.
2. Python обменивает `GEMINI_API_KEY` на одноразовый токен, ограниченный настройкой
   модели, системной инструкцией и инструментом `search_places`.
3. Браузер передаёт PCM mono 16 kHz напрямую в Gemini Live. Ответ PCM 24 kHz
   воспроизводится очередью Web Audio. AudioWorklet сохраняет позицию ресемплинга
   между блоками, включая вход 44,1/48 kHz.
4. Gemini определяет язык, ведёт диалог и вызывает `search_places` со самостоятельным
   английским запросом, разрешив ссылки вроде «второе» или «поближе» из контекста звонка.
5. Вызов проходит через Streamlit component bridge в Python. Сервер проверяет
   аргументы, округляет старт, сохраняет пользовательские фильтры и запускает
   существующий `generate_recommendations(..., use_llm=False)`.
6. Модель получает только разрешённые поля POI. Радиус можно сузить, но нельзя
   расширить сверх настройки пользователя. Автоматический перенос старта по
   ориентиру отключён в этом режиме. Координат в ответе инструмента нет.
7. После отправки результата модели браузер подтверждает его использование:
   только тогда обновляются обычные карточки, карта и маршрут. Отменённый вызов их не меняет.
8. Расшифровка речи передаётся в основной чат с объединением обновлений раз в 600 мс.
   Вопрос, устный ответ и результат инструмента связываются по идентификатору реплики.
   Создание чата не пересоздаёт iframe и не обрывает микрофон. Завершение генерации
   перед вызовом инструмента не считается завершением всей голосовой реплики.

Временные токены выдаются через официальный REST API, аудио передаётся через
`BidiGenerateContentConstrained`. Зависимости SDK/CDN и второй веб-сервер не нужны.
События браузера подтверждаются по одному, чтобы rerun Streamlit не терял вызовы;
повторные идентификаторы инструментов переиспользуют результат поиска.

## Поведение

- Язык речи следует последней реплике, язык карточек — интерфейсу.
- Панель звонка содержит состояние «слушаю / ищу / отвечаю», управление микрофоном
  и завершением. Голосовой диалог отображается в общей ленте с меткой источника ввода.
- Новая выдача автоматически вписывается в карту; маршрут и таймлайн строятся тем же
  кодом, что для текстового запроса. Карта сохраняется после благодарности или уточнения
  без нового поиска. Для запроса построить/изменить маршрут модель вызывает поиск заново.
- Контекст сохраняется на протяжении соединения; текстовая история в него не загружается.
- При событии `interrupted` очередь аудио немедленно очищается. Эхо подавляет браузер;
  в шуме и без наушников возможны ложные перебивания.
- «Выключить микрофон» выключает дорожку и отправляет `audioStreamEnd`.
- «Завершить», смена чата, отключение режима и закрытие страницы освобождают
  микрофон, WebSocket, worklet и AudioContext.
- Сессия ограничена 10 минутами; переподключение запускается пользователем.
  Настройки фиксируются при подключении, изменения применяются к новому разговору.
- Ошибки ключа, квоты и сети показываются без секретов и тела ответа провайдера.
- До разрешения микрофона/подключения звук не передаётся. Наш сервер не хранит аудио;
  расшифровка и выдача остаются в истории текущей Streamlit-сессии после завершения
  звонка. Повторное открытие чата не вызывает генерацию или поиск заново.
- Это экспериментальный голосовой интерфейс: факты проверяются поиском, но устную
  формулировку создаёт модель. Сверяйте режим работы и расстояния с карточками.
  Произношение названий Астаны и качество казахского требуют пользовательского теста.

## Запуск и проверки

В `.env`: `GEMINI_API_KEY` и, опционально, `GEMINI_LIVE_MODEL`.
Запуск: `uv run --locked streamlit run frontend/app.py`.
Не включайте платный биллинг ради первого теста; квоты Free Tier зависят от проекта.
На бесплатном тарифе Google может использовать данные для улучшения продуктов.
Публичному развёртыванию дополнительно нужны вход пользователей и лимиты выдачи
токенов на пользователя: прототип рассчитан на локальное демо.

```bash
uv run --locked python -m pytest tests -q
node --test tests/live_voice_audio.test.mjs tests/live_voice_session.test.mjs
```

Ручная проверка в браузере:

1. Разрешить микрофон, спросить по-русски про кафе; услышать ответ, увидеть реальные карточки.
2. Спросить «А поближе?»; проверить сохранение контекста и новый поиск.
3. Поменять язык речи на казахский, английский и китайский; проверить язык ответа.
4. Перебить длинный ответ; старый звук должен остановиться.
5. Выключить микрофон, закончить звонок и открыть новый чат: индикатор микрофона должен погаснуть.
6. Отклонить разрешение, отключить сеть или исчерпать квоту: текстовый чат остаётся доступен.

Проверено 18.10.2026: 183 Python-теста, 5 Node-тестов; Streamlit AppTest и отображение
панели в Chrome. Настоящий Gemini Live принял синтетическую русскую аудиозапись,
распознал запрос, вызвал локальный поиск и вернул PCM-аудио. Последующие текстовые
уточнения в той же сессии дали голосовые ответы на казахском, английском и китайском.
Отмена вызовов, перебивание, выключение микрофона и поздний ответ авторизации
проверены тестом браузерного компонента с подставными устройствами.
AppTest дополнительно воспроизводит полный путь голосового запроса: частичная
расшифровка → поиск → карточки → карта и маршрут → благодарность → завершение →
открытие истории. Проверяется отсутствие повторного вызова модели и сохранение
одного iframe при создании чата.
Разговор через физический микрофон и качество произношения должен проверить человек.
