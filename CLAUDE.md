# CLAUDE.md — Build with AI · Track 1: ИИ-помощник по прогулкам в Астане

Хакатон «Build with AI» (Школа ИИ и науки о данных), задача от НИЦ Smart City.
Команда из двух человек. Язык общения и документов: русский. Код и комментарии: английский.

## Цель

RAG-система, которая в реальном времени советует, куда сходить в Астане, исходя из локации,
предпочтений и контекста пользователя. Выдача на запрос: 1-3 пункта, у каждого:
- короткое «почему» (мотивация);
- примерное время на посещение;
- «что делать там» (действие / маршрут);
- расстояние и время пешком;
- пометка источника: `poi_data` (факт из датасета) или `generated_idea` (идея модели);
- уровень уверенности по режиму работы.

## Что сдаём (6 артефактов)

1. Концепция продукта (идея, ЦА, сценарии).
2. Демо/прототип (UI или чат, несколько сценариев).
3. Описание RAG-подхода (высокоуровневое, без низкоуровневых схем).
4. Набор тестовых сценариев: вход + ожидаемый тип ответа.
5. Презентация 5-7 минут (бизнес-идея, ограничения, риски, план развития).
6. Этика и приватность: локация, недостоверные данные, безопасность.

Формат сдачи: репозиторий, презентация PDF, документ со сценариями и ограничениями,
демо-видео на YouTube.

## Критерии жюри (по важности)

1. Релевантность и полезность. 2. Контекстуальность (расстояние, время, режим работы).
3. Качество объяснений. 4. UX и понятность демо. 5. Креативность.
6. Этика и приватность. 7. Завершённость (документация, сценарии, презентация).

## Жёсткие требования к поведению системы

- Явно показывать, какие данные использованы: локация, фильтры, теги.
- Никогда не утверждать «открыто сейчас» без данных о часах работы; всегда указывать уверенность
  (`confirmed_open` / `likely_open` / `unknown` / `likely_closed`).
- Честно маркировать источник каждой рекомендации: `poi_data` или `generated_idea`.
- Не выдумывать места, которых нет в retrieval-результатах. Генерируется только объяснение и план,
  а не сами POI.
- Приватность: не хранить точные координаты пользователя. В логах округлять до ~100 м
  или не логировать вовсе. Никаких персональных данных.
- Сомнительные или неполные данные (закрытые места, временные события) обрабатываем явно
  и описываем в документе об ограничениях.

## Стретч-цели (для баллов за креатив, по возможности)

Мини-маршрут из 3 мест · мультиязычность (ru/kk/en) · группы 3-5 человек · локальные события ·
доступность для маломобильных.

## Роли и ветки

Не пушить в `main`. Каждый работает в своей ветке, в `main` только через PR.

**Роль A: данные и поиск** (ветка `feat/data-retrieval`, папки `data/`, `backend/retrieval/`)
- Автосбор POI (OSM Overpass API, при необходимости 2GIS), очистка, нормализация. Скрипт воспроизводимый.
- Эмбеддинги и векторная БД (Chroma), индексация названий, описаний, тегов.
- `retrieve()`: фильтр по расстоянию (haversine), категории, режиму работы, ранжирование.
- Логика уверенности по часам работы.
- Тестовые сценарии (5-8 кейсов) в `docs/test_scenarios.md`.
- Документ по этике и приватности: `docs/ethics_privacy.md`.

**Роль B: генерация и интерфейс** (ветка `feat/generation-ui`, папки `backend/generation/`, `backend/api/`, `frontend/`)
- Промпт и вызов Claude: «почему / время / что делать», маркировка источника.
- FastAPI `/recommend`, мини-маршрут из 3 мест.
- UI (Streamlit или Gradio): ввод локации, фильтры, карточки рекомендаций.
- README, описание RAG-подхода, презентация, запись демо.

Пока A не закончил реальный поиск, B работает на заглушке `backend/retrieval/stub.py`
с 10-15 тестовыми POI и тем же интерфейсом.

## Контракт между A и B (не менять без согласования обоих)

### Схема POI (`data/poi.json`, список объектов)

```json
{
  "id": "osm_node_123456",
  "name": "Кофейня Пример",
  "lat": 51.1283,
  "lon": 71.4305,
  "description": "Короткое описание",
  "category": "cafe",
  "tags": ["coffee", "quiet", "wifi", "power_outlets"],
  "opening_hours": "Mo-Su 09:00-22:00",
  "contacts": {"phone": null, "website": null},
  "rating": null,
  "source": "osm",
  "collected_at": "2026-10-16"
}
```
Поля `description`, `opening_hours`, `contacts`, `rating` могут быть `null`. Это нормально,
система обязана корректно обрабатывать пропуски.

### Retrieval (Python)

```python
def retrieve(query: str, lat: float, lon: float, *,
             max_distance_m: int = 2000,
             categories: list[str] | None = None,
             now_iso: str | None = None,
             top_k: int = 8) -> list[Candidate]: ...
```
`Candidate`: `poi` (объект POI) + `distance_m` + `walk_min` + `relevance` (0-1) +
`open_status` (`confirmed_open | likely_open | unknown | likely_closed`) + `open_reason` (строка).

### API `POST /recommend`

Запрос:
```json
{"query": "тихое место с кофе и розеткой", "lat": 51.1283, "lon": 71.4305,
 "max_distance_m": 1500, "lang": "ru", "group_size": 1, "accessible": false, "now_iso": null}
```
Ответ:
```json
{
  "used_data": {"location": "rounded_100m", "filters": ["cafe"], "tags": ["quiet", "power_outlets"]},
  "recommendations": [
    {"poi_id": "osm_node_123456", "name": "...", "distance_m": 300, "walk_min": 4,
     "why": "...", "visit_min": 45, "what_to_do": "...",
     "open_status": "unknown", "confidence_note": "Часы работы не указаны в данных",
     "source": "poi_data"}
  ],
  "route": null,
  "disclaimer": "..."
}
```

## Технологии

- Python 3.11+, FastAPI, Streamlit (или Gradio), Chroma.
- LLM: Claude через Anthropic API. Модель задаётся переменной `ANTHROPIC_MODEL`
  (по умолчанию `claude-sonnet-5-5`, для быстрых тестов `claude-haiku-5-5`).
- Эмбеддинги: у Anthropic API нет эмбеддингов, используем локальную мультиязычную модель
  `sentence-transformers` (ru/kk/en).
- Ключи только в `.env` (в `.gitignore`), в репо лежит `.env.example`.
